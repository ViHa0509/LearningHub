Vercel deploy flow

How a change reaches the hosted Learning Hub: local gates, GitHub Actions, a database migration, the Vercel Deploy Hook, then the public address. Vercel does not deploy main on its own (vercel.json: git.deploymentEnabled.main = false); only CI starts a production deploy, and only after the migration.

1 · Your PC

Claude Code hooks from ai-sdlc-kit, configured in .sdlc/gates.json

1git commit

Commit gate runs backend pytest (timeout 1800 s), ruff, mypy, frontend npm test, lint, build. Any failure blocks the commit.

2git push origin main

Push gate runs the full e2e suite (npm run e2e, timeout 1500 s). A failure blocks the push.

↓

2 · GitHub Actions — .github/workflows/ci.yml

Runs on every push to main and every pull request; a newer push to the same ref cancels the older CI run

3backend job

Postgres service pgvector/pgvector:pg17; pytest, ruff, mypy.

3frontend job

npm test, npm run lint, npm run build.

both pass
4e2e job

Playwright on Edge with its own Postgres; screenshots kept as a run artifact for 14 days.

all three pass, and the event is a push to main (never a pull request or a tag)
5deploy job

One deploy at a time (concurrency: deploy-production, never cancelled mid-migration), 15-minute limit.

5a · Check the secrets

LH_MIGRATE_DATABASE_URL and VERCEL_DEPLOY_HOOK_URL both set? If not: prints “Deploy secrets are not set; skipping the production deploy.” and stops (job still green).

5b · Install

Checkout, Python 3.12, pip install -r requirements.txt.

5c · Migrate production DB

alembic upgrade head against Supabase Session pooler :5432. A failure fails the job; the hook is never called.

5d · Trigger Vercel

curl --fail -X POST "$VERCEL_DEPLOY_HOOK_URL"

↓

3 · Vercel — vercel.json

The Deploy Hook (Project Settings → Git → Deploy Hooks, branch main) starts a production build of main · region icn1 · Hobby plan

6Build service web

Root frontend/, framework Vite; SPA rewrite of every path to /index.html.

6Build service api

Root backend/, entrypoint app.main:app; packages from pyproject.toml; build copies roadmaps/ and news/ into _data/.

7Production deployment

Environment values (Production only): LH_SERVERLESS, LH_DATABASE_URL, LH_SECRET_KEY, LH_SUPABASE_*, LH_PUBLIC_URL… Live at <project>.vercel.app.

↓

4 · Serving requests

The public address stays the same across deploys

Browser

Opens the workers.dev address (LH_PUBLIC_URL; OAuth callbacks use it too).

Cloudflare Worker learninghub

Forwards every request unchanged to ORIGIN, set once with deploy/worker/set-origin.ps1 https://<project>.vercel.app.

Vercel rewrites

/api/* → api (serverless FastAPI); everything else → web.

Supabase

Postgres via Transaction pooler :6543 (runtime); note files in the private Storage bucket learninghub.

Where a deploy stops

  • A commit or push gate fails: nothing leaves your PC.
  • Any CI job fails: the deploy job does not run.
  • Secrets missing: deploy skipped, CI still green.
  • Migration fails: the hook is not called; the old code keeps running.
  • Vercel build fails: the previous deployment stays live.

Where the two secrets come from

  • VERCEL_DEPLOY_HOOK_URL: Vercel → Project Settings → Git → Deploy Hooks → create for main, copy the URL.
  • LH_MIGRATE_DATABASE_URL: Supabase → Connect → Session pooler (port 5432) as postgresql+psycopg://…?sslmode=require.
  • Both go in GitHub → Settings → Secrets and variables → Actions.

Not a Vercel deploy

  • Pull requests: checks only.
  • Tag v*: release.yml builds the Docker image to ghcr.io and a GitHub Release.
  • Changing where the Worker points: run set-origin.ps1 by hand.
