# Proposal

## Why

Research done with Claude ends up as HTML files scattered across folders, and even when saved in Knowledge Hub it is forgotten, because nothing ties a file to *where it fits* in what is being learned. This first slice gives every past research file a fixed place on a roadmap (for example `backend > caching > redis`) so it can be found again by position instead of by filename, and it gives the author a tool they use from day one, before any AI feature exists.

## What Changes

- Add hand-written roadmap definitions as YAML files (1-2 domains to start, for example Backend and DevOps), loaded by the backend as the knowledge skeleton. No content is imported from roadmap.sh.
- Add upload of Claude-generated HTML research files: the raw file is kept in local file storage (behind a storage interface so a cloud store can replace it later), and its title and readable text are extracted into a note in Postgres.
- Let the user attach each note to one roadmap node, and change or remove that link later.
- Add the web UI shell: a left sidebar listing learned items grouped by domain, and a center roadmap map whose nodes show which ones have notes. Selecting an item in one view highlights it in the other. The right-side agent panel is reserved in the layout but is empty in this slice.
- Let the user open a note to read the original HTML again.
- Out of scope: any LLM call (auto-classification, summaries, chat), multi-provider setup, Knowledge Hub connector, journal/timeline, cloud storage, authentication (single local user), importing roadmap.sh data, HTML files not generated by Claude.

## Capabilities

### New Capabilities

- `roadmap-catalog`: loading and serving hand-written roadmap definitions (domains, nodes, parent/child structure) from YAML, with validation of node ids.
- `knowledge-import`: importing a Claude-generated HTML research file into a stored note (raw file kept, title and text extracted), plus listing, reading and deleting notes.
- `node-linking`: attaching a note to a roadmap node, changing or removing the link, and querying notes per node and nodes with notes.
- `learning-views`: the web views over notes and roadmaps: the left learned-items list, the center roadmap map with note markers, and their two-way selection.

### Modified Capabilities

None. The project has no existing specs.

## Impact

- New code: `backend/` (FastAPI service, Postgres schema and migrations, local file storage adapter, HTML extraction), `frontend/` (React app with the three-pane layout), `roadmaps/*.yaml`.
- New dependencies: FastAPI, a Postgres driver and migration tool, an HTML parsing library, React and a graph/map rendering library (chosen in design.md).
- Local runtime: Postgres (for example via docker-compose) and a local folder for uploaded files.
- Process: this is the first change built through the AI-native loop (spec -> plan -> code -> review -> verify) using Kit v0 from the separate `ai-sdlc-kit` repository (CLAUDE.md, REVIEW.md, verifier subagent); that kit is its own change in its own repo.
