# knowledge-import Specification

## Purpose
Turns research pages generated by Claude (standalone HTML files) into stored notes that keep the original file and a readable title and text, so past research can be found and reread.

## Requirements

### Requirement: Import Claude-generated HTML files
The system SHALL import one or more HTML files in a single request and create one note per file. The supported input is a standalone HTML page as produced by Claude (one `.html` or `.htm` file, inline CSS and scripts allowed). Other HTML may import but is not a supported input.

#### Scenario: Import one file
- **WHEN** the user imports `redis-eviction.html`
- **THEN** one note is created and returned with its id, title, original filename, size and import time

#### Scenario: Import several files at once
- **WHEN** the user imports three HTML files in one request
- **THEN** the result lists each file with its own outcome (created, duplicate or rejected), and a rejected file does not stop the others

### Requirement: Reject unsupported files
The system SHALL reject a file that has no `.html`, `.htm` or `.pdf` extension, is empty, is not decodable as text (HTML), is not a readable PDF or has no text to import (PDF), or is larger than 10 MB, and SHALL report the reason per file.

#### Scenario: Wrong file type
- **WHEN** the user imports `notes.docx`
- **THEN** that file is rejected with the reason "not an HTML or PDF file" and no note is created

#### Scenario: File too large
- **WHEN** the user imports an HTML file of 12 MB
- **THEN** that file is rejected with the reason "larger than 10 MB"

#### Scenario: Scanned PDF
- **WHEN** the user imports a PDF without a text layer
- **THEN** that file is rejected with the reason that it has no text to import

### Requirement: Keep the original file unchanged
The system SHALL store an imported HTML file byte for byte, so that the original page can be shown again exactly as it was. An imported PDF is stored as a generated HTML page holding its text (paragraphs and lists, every character escaped), titled after the PDF's first line or file name.

#### Scenario: Original is preserved
- **WHEN** the user downloads the original of a note imported from HTML
- **THEN** the bytes are identical to the imported file

#### Scenario: PDF becomes a note
- **WHEN** the user imports `docker-basics.pdf` whose text starts with "Docker basics" and has a bullet "• images"
- **THEN** a note titled "Docker basics" is created, its page shows the text with "images" as a list item, and markup characters from the PDF are shown as text

### Requirement: Extract title and readable text
The system SHALL give each note a title and a plain-text body taken from the page. The title is the page `<title>`, else the first `<h1>`, else the filename without extension. The body excludes scripts, styles and markup.

#### Scenario: Title from the title tag
- **WHEN** a page with `<title>Redis eviction policies</title>` is imported
- **THEN** the note title is `Redis eviction policies`

#### Scenario: No title tag
- **WHEN** a page without `<title>` but with `<h1>JWT vs sessions</h1>` is imported
- **THEN** the note title is `JWT vs sessions`

#### Scenario: Scripts are not text
- **WHEN** a page contains inline JavaScript and CSS
- **THEN** none of that code appears in the note's text

### Requirement: Detect duplicate imports
The system SHALL treat a file whose content is identical to an already imported file as a duplicate: it creates no new note and returns the existing one.

#### Scenario: Same file imported twice
- **GIVEN** `redis-eviction.html` was imported before
- **WHEN** the same file is imported again, even under another name
- **THEN** the outcome is "duplicate" with the id of the existing note

### Requirement: List, read, rename and delete notes
The system SHALL let the user list notes (newest first), read one note (title, text, metadata, link, archived state, page hash), change its title, archive and restore it, and delete it. Deleting a note also deletes its stored original file. The list MUST exclude archived notes unless the client asks for archived notes, in which case it returns only those.

#### Scenario: Rename a note
- **WHEN** the user changes a note's title to `Redis: eviction and TTL`
- **THEN** the note shows the new title and the original file is unchanged

#### Scenario: Delete a note
- **WHEN** the user deletes a note
- **THEN** the note no longer appears in any list and its original file is removed from storage

#### Scenario: Archive a note
- **GIVEN** a note linked to `backend/redis`
- **WHEN** the user archives it
- **THEN** the default note list no longer contains it, the list of archived notes does, and it keeps its title, link and original file

#### Scenario: Restore a note
- **GIVEN** an archived note
- **WHEN** the user restores it
- **THEN** it is back in the default note list with its link, and no longer in the archived list

### Requirement: Show the original page safely
The system SHALL display an original page isolated from the application: its scripts MUST NOT be able to read or change application data, cookies or storage, or call the application's API as the user.

#### Scenario: Page with scripts is opened
- **WHEN** the user opens a note whose original page runs JavaScript
- **THEN** the page renders inside an isolated frame and its scripts cannot access the application

### Requirement: Replace a note's page
The system SHALL let the user replace a note's stored page with new HTML. The note keeps its title, link and archived state, its searchable text is taken from the new page, and the old file is removed once no note uses it. The system MUST reject an empty or oversized page, a page identical to another note's page, and a save based on a page that has since changed.

#### Scenario: Save edited HTML
- **GIVEN** a note titled `Redis TTL` linked to `backend/redis`
- **WHEN** the user saves new HTML containing `volatile-lru`
- **THEN** the original page returns the new HTML, a search for `volatile-lru` finds the note, and its title and link are unchanged

#### Scenario: Stale edit is refused
- **GIVEN** the user opened the editor, and the page was saved from another tab since
- **WHEN** the user saves from the first editor
- **THEN** the save is refused with a conflict and the newer page is kept

#### Scenario: Empty page is refused
- **WHEN** the user saves an empty page
- **THEN** the save is refused and the page is unchanged

#### Scenario: Page identical to another note
- **WHEN** the user saves HTML identical to another note's page
- **THEN** the save is refused with a conflict and the page is unchanged
